Setup & FAQ

For version 1.4.0. This page assumes you are comfortable with servers, ports and API keys — if that is not you, the quick start guide covers the same setup in plain language.

Choosing a provider

Any of these work. The only real decision is whether the review text leaves your computer.

Local setup

Ollama

Install Ollama, then:

  • ollama pull llama3.2 — or any model you prefer
  • ollama serve

In settings choose Ollama, press Test connection, and the model field will autocomplete from the models you actually have installed. Running it on another port or machine? Change Server endpoint.

LM Studio, llama.cpp, Jan, vLLM and friends

Start your server with its OpenAI-compatible API enabled, then in settings pick Local server and choose your runtime from the preset list — the address is filled in for you:

Hosted API setup

Pick the provider, paste its API key, press Test connection. That check uses the provider's free model-list endpoint, so it validates your key without spending any tokens.

Once saved, a key is encrypted and never shown again — the field displays a ✓ Saved badge. Leave it blank to keep the stored key; use ✕ to remove it.

Settings worth knowing

Review scope

  • All — everything collected, in Google's own relevance order
  • Recent — sorts the page by newest first, then takes the newest N
  • 1 / 3 / 6 / 12 months — sorted newest-first and filtered by date

Analysis depth

How many collected reviews actually reach the model: Quick (~100), Balanced (~250) or Thorough (~500). More is slower, and on a local model needs a bigger context window. The result header always tells you the real number, for example "113 of 1,043 reviews analyzed".

Reviews are not simply truncated — every 1–2★ review is kept, since complaints are the scarcest signal, and the rest are sampled evenly across the whole time range.

Context window (local models)

Set this to match what your model actually supports. If it is too small for the chosen depth, the extension automatically trims the prompt to fit rather than overflowing it, and says so in the service-worker console.

Troubleshooting

"Ollama is not ready" / "Cannot reach Ollama at…"

The provider is checked before any reviews are collected, so this appears within a second and nothing was scraped. The server is not running, or is on a different address: start it with ollama serve, or correct Server endpoint in settings, then press Test connection to confirm.

The same message with a provider name in it — "Gemini is not ready" — means that provider refused the check, usually a wrong or expired API key. Analyze anyway is there for the uncommon setup that fails the check but works regardless: the check calls the provider's model-list endpoint, and a self-hosted server can serve chat without offering one.

My custom endpoint will not connect

  • Include the version path — usually /v1, not just host and port
  • If it is not on localhost, Chrome will ask permission when you save. Accept it
  • Confirm the server was started with its OpenAI-compatible API enabled

The summary is in the wrong language

Set Output language in the Analysis section. Auto follows the reviews' own language; pick a specific language to pin it.

The time filters seem to be ignored

Review dates are read from the page text, and only English relative dates ("3 months ago") are understood. On a non-English Maps interface most dates cannot be parsed — those reviews are kept rather than silently dropped, and the result screen warns you when it happens.

It is slow

  • Lower Analysis depth to Quick
  • Reduce Maximum reviews to collect
  • Use a smaller local model, or a hosted provider like Groq
  • Press ⚡ Summarize Now mid-collection to stop gathering and summarize what is in hand

I want a fresh result, not the cached one

↺ Re-analyze reuses the collected reviews and just re-runs the AI. ⟳ Fresh re-scrapes the page from scratch.

What it does when you are not using it

Nothing. There is no background activity, no scheduled work and no connection kept open. The extension's worker wakes only to make the request you asked for, and the content script on a Maps page does nothing until the popup tells it to. Close the popup mid-analysis and the run is abandoned — the result is discarded, though the page may finish the scroll already in progress. Cancel stops it properly.
